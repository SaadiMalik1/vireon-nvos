# Contributor Guide

VIREON is an open scientific ecosystem. We welcome contributions, but we prioritize **scientific rigor** over velocity.

## Adding a New Plugin
Before submitting a Pull Request for a new methodology, hardware model, or artifact generator, you must satisfy the following:

1. **Implement `IPlugin`:** Your class must fulfill the interface requirements.
2. **Define the `ScientificContract`:** You must explicitly list all mathematical, numerical, and physiological assumptions.
3. **Declare an SRL:** Assign a Scientific Readiness Level (SRL).
4. **Knowledge Graph Integration:** If your plugin introduces a *new* mathematical assumption not currently in the `vireon-knowledge` ontology, you must add it to the graph.

## Scientific Readiness Levels (SRL)
To prevent "garbage in, garbage out", VIREON strictly categorizes plugins by their validation maturity. You must explicitly declare the SRL in your `ScientificContract`.

- **SRL-0 (Unverified Idea):** Code compiles. No mathematical proof or empirical validation. (Not accepted into main).
- **SRL-1 (Mathematical Proof):** The mathematical derivation of the algorithm is provided in the PR or linked paper.
- **SRL-2 (Synthetic Validation):** Algorithm is tested against deterministic, noiseless synthetic signals (e.g. `SyntheticAlpha10Hz`).
- **SRL-3 (Numerical Equivalence):** Algorithm matches the output of an established library (like SciPy or MNE) to a specified tolerance (e.g., `RMSE < 1e-6`).
- **SRL-4 (Adversarial Validation):** Algorithm survives perturbation testing in `vireon-validation` (e.g. impedance drift, packet loss).
- **SRL-5 (Empirical Validation):** Algorithm is validated against an empirical `vireon-corpus` dataset with known ground truth.
- **SRL-6 (Physiological Validation):** Algorithm's outputs align with known physiological literature bounds (e.g., source localization matches fMRI priors).
- **SRL-7 (Multi-Lab Reproducibility):** Evidence bundle generated by the plugin is independently reproduced by an external lab.
- **SRL-8 (Clinical Retrospective):** Validated against retrospective clinical trial data.
- **SRL-9 (Regulatory Grade):** Accepted by regulatory bodies (e.g. FDA MDDT program) as valid evidence.

## Adding a Benchmark or Dataset
Datasets are treated as scientific assets.
- You must include a JSON manifest detailing the Acquisition hardware, Sampling rate, Montage, and Licensing.
- You must provide the cryptographic Hash fingerprint (`sha256`) of the dataset to ensure provenance tracking by the Evidence Engine.

## Code Standards
- We strictly enforce type hints (`mypy`).
- Scientific constants (e.g., the speed of light, tissue conductivities) must never be hardcoded "magic numbers". They must be imported from the `vireon-knowledge` ontology.
