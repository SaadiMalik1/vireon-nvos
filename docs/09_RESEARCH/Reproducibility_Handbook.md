# Reproducibility Handbook

The Reproducibility Handbook outlines the practical methodologies for ensuring that every piece of evidence generated by VIREON can be independently verified.

## The Verification Hierarchy
1. **SRL-1 to SRL-3 (Mathematical Equivalence):** Checked continuously via `vireon-verification` CI pipelines running against `vireon-reference`. 
2. **SRL-4 to SRL-5 (Empirical Validity):** Checked by mapping algorithms against standard empirical datasets (`vireon-corpus`). For example, the `PhysioNetMotorImageryProvider` automatically streams authentic biological data into the evaluation pipeline.
3. **SRL-6 to SRL-9 (Regulatory Equivalence):** Checked via Cartesian Benchmark Campaigns mapping exact failure boundaries into the `evidence_graph.json` ontologies.

## The Reproducibility CLI
Any canonical paper ingested into the VIREON Knowledge Graph can be reproduced with a single command:
```bash
vireon reproduce 10.1016/j.neuroimage.2023.111111
```
The Reproducibility Engine (`vireon_lab.cli`) automatically:
- Resolves the exact Git hashes of the algorithms used.
- Retrieves the precise PhysioNet or local dataset mapped in the `manifest.yaml`.
- Re-runs the Execution DAG.
- Computes empirical metrics between the original published evidence and the newly generated bundle.
- Emits a Reproducibility Summary directly in the resulting `evidence.md` file.

*Note: In Phase E, dataset resolution relies on strictly mapped internal providers (e.g. `PhysioNetMotorImageryProvider`) and locally cached archives rather than dynamic global BIDS fetching.*

## The Failure Atlas Integration
When reproducing a paper, a researcher can inject a `--factor 10` flag to run an adversarial attack on the original paper's claims. If the paper claimed "95% accuracy on Motor Imagery", the CLI will instantiate Hardware Twins (e.g., `AmplifierTwin`, `TelemetryTwin`) and progressively increase thermal noise and packet loss until the accuracy degrades. 

This generates an operational envelope which is logged to the local `evidence_graph.json` for subsequent querying. By generating semantic edges linking the empirical execution back to the original paper's claims, VIREON allows reviewers to strictly verify the algorithmic boundaries without needing remote integration.
