# Reproducibility Handbook

The Reproducibility Handbook outlines the practical methodologies for ensuring that every piece of evidence generated by VIREON can be independently verified.

## The Verification Hierarchy
1. **SRL-1 to SRL-3 (Mathematical Equivalence):** Checked continuously via `vireon-verification` CI pipelines running against `vireon-reference`. (Status: [FULLY IMPLEMENTED]).
2. **SRL-4 to SRL-5 (Empirical Validity):** Checked by mapping algorithms against standard empirical datasets (`vireon-corpus`). (Status: [FULLY IMPLEMENTED]).
3. **SRL-6 to SRL-9 (Regulatory Equivalence):** Checked via Massive Factorial Campaigns mapping exact clinical failure boundaries into the Failure Atlas. (Status: [WIP / PARTIALLY STUBBED]).

## The Reproducibility CLI
Any canonical paper ingested into the VIREON Knowledge Graph can be reproduced with a single command:
```bash
vireon reproduce 10.1016/j.neuroimage.2023.111111
```
The Reproducibility Engine (`vireon_lab.cli`) automatically:
- Resolves the exact Git hashes of the algorithms used.
- Instantiates identical Digital Twins with the same stochastic seeds.
- Re-runs the Execution DAG.
- Computes the Intraclass Correlation (ICC) and Bland-Altman agreement between the original published evidence and the newly generated bundle.
- Emits a final Scientific Reproducibility Index (SRI).

- **Status**: [FULLY IMPLEMENTED] - The core `vireon reproduce DOI` capability is functional. However, the automated fetching of datasets from external BIDS archives for empirical reproduction is currently [STUBBED] and relies on local caching.

## The Failure Atlas Integration
When reproducing a paper, a researcher can inject a `--factor 10` flag to run an adversarial attack on the original paper's claims. If the paper claimed "95% accuracy on Motor Imagery", the CLI will instantiate Hardware Twins (e.g., `AmplifierTwin`, `TelemetryTwin`) and progressively increase thermal noise and packet loss until the accuracy degrades. 

This generates an operational envelope which is logged to the Failure Atlas.

- **Status**: [STUBBED] - The adversarial injection grid exists, but the automated routing of bounds to the remote `Failure Atlas` ontology is a pending API integration.
